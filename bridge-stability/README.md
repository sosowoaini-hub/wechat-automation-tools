# 微信桥稳定性补丁

给基于 `wechatauto` / `dsh-wechat-bridge`（MIT 上游）的微信桥补三个「实际用会疼」的地方。

## 三个补丁

1. **发送锁超时保护**（借鉴 WeChatAgent 的 `timed_mutex`）
   - 问题：原桥用 `threading.Lock()` 无超时。一次 UIA 发送卡死后线程攥着锁不放，后续所有发送（含预热）永久阻塞，整个桥假死。
   - 做法：`_send_guard(timeout=90)` 用 `acquire(timeout=90)`，拿不到就记日志并跳过这次，让后续消息有机会继续。

2. **磁盘持久化去重**
   - 问题：原桥的去重记录只在内存，重启就丢；桥重启后兜底通道晚醒来会把同一句重复发一遍（"老是发两次一模一样"）。
   - 做法：发送记录落到 `~/.dsh/wx-sent-dedup.json`，启动时加载 1 小时内的记录，写盘保留最多 500 条。

3. **看门狗用日志 mtime 判断假活**（见 `docs/`）
   - 问题：用"消息活动/UIA 窗口/旧错误信号"判断桥是否卡死都会误判（群安静、枚举时机、日志残留）。
   - 做法：只看桥日志文件的 mtime——正常轮询每几分钟写 WAL 告警，真卡死时 mtime 停住。超过 20 分钟没动就重启桥（只重启桥，不碰微信）。

## 用法
`stability.patch` 是对 `wechat_bridge.py`（`main()` 函数内）的 unified diff。对照你的桥源码手工应用即可（行号因版本可能略有出入）：

```bash
patch bridge/wechat_bridge.py < stability.patch
# 或手动按 patch 内容改，重点看 @@ 里的上下文
```

改完重启桥生效。建议先备份原文件。

## 验证
补丁在真实家庭群场景跑过：修好后桥能稳定收发、不再重复发送、卡死能自动恢复。
